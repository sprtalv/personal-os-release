# 当天计划、执行与工作收尾

## 早晨或即时计划

先读取当前目标、长期约束、近期截止与必要历史。制定当天安排前刷新授权工具中的实际待办和日历，注明数据时间；工具不可用时区分已知快照与尚未核验的状态。

结合用户实际精力、可用时段、固定安排、依赖和准备成本，提出可执行的下一步与计划草案。信息不足时保留空白或提出一个影响安排的关键问题，不把一整天填满来掩盖未知。说明重要取舍，把确认决定与建议分开。

仅在已有明确授权覆盖的范围内修改实际待办、优先级、日期或日程。授权已覆盖时直接执行，不重复确认。操作后核验工具返回；档案同步失败与外部操作失败分别报告。

## 执行检查

依次核对已知进展、近期交流、工具状态及约定截止。没有勾选不等于没完成；没有交流记录不等于没做。区分未开始、进行中、完成未记录、等待依赖、主动延期和实际受阻，必要时核实。

发现阻碍时优先帮助明确下一步、所需支持或调整草案，不自动给出人格解释。提醒应有新到期时间、新信息或已约定依据；不因同一状态每天重复催促。

## 课后信息缺口

仅依据已确认课表与实际已知情况检查缺口。课表上的课不能证明当天上过课，课程结束也不能证明有新作业。

先查近期交流是否已经覆盖，再集中询问重要的未明事项，例如“今天这门课有新增作业或截止安排吗？”有新安排时记录来源和时间，按授权创建任务。无新信息就结束本轮，不生成空任务。

## 工作开始

帮助明确本次目标、可验收成果、可用时间和停止条件。区分需要用户决策的问题与可以自主完成的步骤。已有资料足够时不要求重复介绍项目。

对科研等容易连续扩展的工作，约定本次边界、必要检查点和结束后的恢复材料。停止条件是本次约定，不自动推广为长期限制。

## 工作收尾

从本次过程提取：

- 实际完成的成果及可用位置。
- 当前停止点、未解决问题与已尝试方法。
- 等待事项、依赖、可能收到结果的时间。
- 下次可以直接执行的第一步，以及需要的上下文。
- 原先预期与实际差异；需要观察结果时关联回填项。

缺少结果时标明未知，不因“结束工作”把任务标完成。对已完成事项使用实际证据或本人报告的相应依据类型。

## 晚间与概览

晚间读取 [reflection.md](reflection.md) 和 [followup.md](followup.md)，合并访谈、当天收尾及到期回填，避免重复问题。具体时刻由已配置调度决定；未配置不承诺自动发起。

用户问“我现在该做什么”或“给我看总览”时，优先展示当前目标、下一步、近期截止、阻碍、待确认调整和到期回填，标注资料更新时间。不要把档案里的旧任务快照伪装成实时状态。
