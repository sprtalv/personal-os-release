# Build a self-model from evidence

Start with a specific question about a goal, habit, decision, or recurring situation. Save the underlying events before writing a model.

1. Keep observations, the person's own explanations, and assistant hypotheses distinct. Link each interpretation to dated source records.
2. Look for a plausible alternative and a counterexample. Use a case to connect the decision, action, prediction, outcome, and what changed.
3. Put a hypothesis in the current summary only after discussing it with the person; keep its label, scope, and confidence. An acknowledged interpretation is not a fact.
4. If evidence contradicts a conclusion, link the correction and mark the old conclusion superseded or withdrawn. Retain original observations and use the corrected view in future reviews.
5. Revisit only claims that matter to a current choice. A self-model is not a diagnosis or a permanent identity, and it does not launch extra reminders by default.

Use the existing [record](../assets/templates/record.md), [case](../assets/templates/case.md), [insight](../assets/templates/insight.md), and [current summary](../assets/templates/current.md) templates. Use examples from the person only in their private vault.
